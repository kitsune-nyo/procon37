# 日ごとの行動ビジュアライザ

WSL の `code` ディレクトリから起動します。追加パッケージは不要です。

```bash
python3 visualizer.py
```

`make visualizer` でも起動できます。

ブラウザで http://localhost:8765 を開いてください。Windows の Python でも起動できます。ポートを変更する場合は `--port 8766` を指定します。

## 試合を記録する

更新した `hexudon_main.cpp` を再コンパイルして、通常どおり試合を実行します。

```bash
g++ -std=c++17 -O2 hexudon_main.cpp -lcurl -o output/local/hexudon_main
./output/local/hexudon_main
```

実行ごとに `output/replays/match-<時刻>.jsonl` を作成し、設定、受理された役割、日ごとの開始状態（他チーム・渋滞を含む）、送信計画、受理結果を保存します。書き込みはレコードごとに確定し、途中終了しても記録済みの履歴は残ります。`HEXUDON_REPLAY_PATH` で保存先を変更できます。ログにはチームトークンを記録しません。ログ保存に失敗しても試合の送信処理は続行します。

「履歴を更新」でファイル一覧と現在選択しているログを読み直します。実行中のログは、まだ計画がない日を「計画待ち」と表示します。別の保存場所のログは「ファイルを開く」で読み込めます。取り込んだファイルはサーバーに保存しません。

## 見ることができる情報

- 日付、ステップ、再生速度を指定して再生。矢印キーで1ステップ、Spaceで再生・停止。
- 六角形盤面の車両位置、移動経路、道路状況、店の残り在庫。マスにカーソルを合わせて地点番号と座標を確認。
- 車両を選択して経路・履歴を絞り込み。「全車両」で解除。
- 補給相手・燃料の増加、満タン状態での合流、移動開始・到着、待機、うどん取得を表示。行をクリックして該当時刻へ移動。
- 車両別の1日合計の移動時間・待機時間・補給回数と、サーバーへ送った圧縮行動列。
- 翌日の開始状態が記録されていれば、前日終了時の位置・燃料を照合。

`testes.json` や `case_*.json` は盤面設定だけのファイルです。過去の未記録の行動は復元できません。新しいクライアントで実行した試合から行動を振り返れます。

## 再現の意味

受理された計画も含め、ステップごとの行動は `state.cpp` と同じ順序・出発地点の移動コストに基づく予測です。全車の到着を反映してから、うどん取得、補給を行います。巡回車は到着時に燃料を消費し、補給車は燃料を消費しません。移動中の車両の状態上の位置は出発地点です。盤面では移動の進捗を分かりやすくするためアイコンを補間表示します。

開始時刻（step 0）には取得・補給を行いません。在庫と取得済み店舗は日ごとに初期化します。他チームのステップごとの行動は API から取得できないため、他チームの取得による在庫減少は再現していません。最終日や翌日の記録がない日は実測による照合ができません。未受理・送信失敗の計画は画面に明示します。

サーバーはローカルの `127.0.0.1` だけで待ち受けます。終了は Ctrl+C です。

試合サーバーの接続先は既定で `http://localhost:8080` です。`HEXUDON_BASE_URL=http://localhost:18080 ./output/local/hexudon_main` のように環境変数で変更できます。
